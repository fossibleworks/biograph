# Workflow

## Build engine (this fork)
- Every change starts from a tracked **Goal** in Interactor Build. Create it in the web UI, by importing a GitHub issue, or with `ibuild engine goal-create`. The engine breaks it into EngineTasks (investigation → execution → review).
- Work on branch **`goal/<goalId>`** in an isolated worktree. Never commit directly to the default branch **`biograph-fh`**.
- Every change ships through the goal's single PR, which must pass review and CI. For a small change, `ibuild off` allows a hand-opened PR from its own branch.
- Standing rules live in `.build/RULES.md`. Mirrors exist in `.claude/rules/`, `.cursor/rules/`, `.github/instructions/`, and `AGENTS.md`, and are regenerated by Build. Do not hand-edit the managed blocks.

## Upstream conventions (inherited)
- Commit and PR titles follow **Conventional Commits**: types build, chore, ci, docs, feat, fix, perf, refactor, revert, style, test. Types are lower-case and the subject is required. commitlint enforces this. Scopes are common: `fix(linters): ...`, `feat(appointment): ...`.
- Upstream branches are `develop`, plus `version-14/15/16` (stable) and `version-NN-hotfix`. Mergify closes PRs against stable branches unless they come from bot or maintainer accounts. Backports use the `backport <branch>` labels.
- Mergify merges after **1 approval**. Add the `squash` label for a squash merge, or `dont-merge` to block it.
- CODEOWNERS: @akurungadam @Sajinsr.
- In the PR body, put `closes #N`, explain the change, and add screenshots.
