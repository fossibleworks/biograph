This repo is a single Frappe app. Its top-level layout:

- `healthcare/`: the Python app package.
  - `hooks.py`: wires everything into Frappe: `doc_events` (including a wildcard `*` on_submit/on_cancel that creates medical records), `scheduler_events`, `override_doctype_class` (Sales Invoice → `HealthcareSalesInvoice`), `standard_queries`, `doctype_js`, jinja methods and the `on_login` hook.
  - `healthcare/healthcare/`: the module. It contains:
    - `doctype/`: about 139 doctypes. Each has a folder with `<name>.json` (schema), `<name>.py` (controller), `<name>.js` (form script), optional `_list.js`/`_calendar.js`, and `test_<name>.py`.
    - `report/`, `page/`, `dashboard_chart*/`, `number_card/`, `workspace/`, `print_format/`, `web_form/`, `custom_doctype/` (overrides of ERPNext doctypes such as Sales Invoice and Payment Entry), `setup/`, and `api/` (whitelisted endpoints, e.g. `patient_portal.py`).
    - Shared helpers live in `utils.py`.
  - `controllers/`: shared controllers (`service_request_controller.py`) and `queries.py`.
  - `regional/india/`: country-specific code (ABDM).
  - `patches/` and `patches.txt`: versioned migration patches (`v15_0`, `v16_0`, …).
  - `setup.py` and `install.py` / `uninstall.py` / `after_migrate.py`: install-time fixtures and custom fields.
  - `public/`: desk JS bundle, images, and the built portal assets.
  - `www/`: web routes. `patient_portal.html` is generated by the portal build.
  - `tests/`: shared test bootstrap (`HealthcareTestSuite`).
- `patient_portal/`: Vue SPA source. It calls the Frappe REST/RPC endpoints in `healthcare/healthcare/api/patient_portal.py` through frappe-ui resources. Its build output goes into `healthcare/public/` and `healthcare/www/patient_portal.html`.
- `wiki/`: design docs and usage docs.

**Dependency direction:** `healthcare` imports from `frappe` and `erpnext`. Neither imports back from `healthcare`. ERPNext behaviour is extended through hooks and overrides, not by editing ERPNext. Desk JS talks to the server through `frappe.call` against `@frappe.whitelist()` methods.
