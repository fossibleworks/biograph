Don't hand-edit the following. Regenerate them with their tool instead.

- **`healthcare/public/frontend/`**: built patient-portal bundle with hashed `assets/patient_portal-<hash>.js|.css|.js.map`, plus `index.html` and `manifest.json`. Rebuild from `patient_portal/` with `yarn build`. Note that `vite.config.js` currently sets `outDir` to `healthcare/public/patient_portal/assets`, which differs from the committed `public/frontend/` path. Check which path is actually served before rebuilding.
- **`healthcare/www/patient_portal.html`**: written by the frappe-ui Vite plugin (`buildConfig.indexHtmlPath`).
- **`patient_portal/auto-imports.d.ts` and `patient_portal/components.d.ts`**: type stubs generated by the frappe-ui/Vite plugins.
- **`healthcare/locale/main.pot`**: regenerated weekly by the `generate-pot-file` workflow (`.github/helper/update_pot_file.sh`). The `*.po` translations come from Crowdin PRs ("fix: sync translations from crowdin").
- **`healthcare/__init__.py` `__version__`**: bumped by semantic-release (`.releaserc` prepareCmd). Don't edit it by hand.
- **DocType `.json` files** (`doctype/*/*.json`, workspaces, reports, number cards, dashboard charts, print formats, web forms): Frappe metadata, normally exported from the Desk UI with developer mode. Hand edits must stay valid against the Frappe schema, and `modified` timestamps must be bumped so `migrate` picks them up.
- **Lockfiles**: `yarn.lock` at the root.
- **Ignored outputs** (`.gitignore`): `dist/`, `node_modules/`, `*.egg-info`, `__pycache__/`, `healthcare/docs/current`, `patient_portal/dist`.
- **`healthcare/public/node_modules`** is a committed **symlink** to a developer's local bench path (`/home/hm/bench-v16/...`). It is an accident and should not be modified or replicated.
- **`.secrets.baseline`**: maintained with `detect-secrets scan --baseline`.
