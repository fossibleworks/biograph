Do not hand-edit these. Regenerate them from their source.

- **Built patient portal:** `healthcare/public/frontend/` (hashed `assets/patient_portal-*.js/.css/.map`, `index.html`, `manifest.json`) is Vite output committed to the repo. `healthcare/www/patient_portal.html` is generated by the frappe-ui Vite plugin (`indexHtmlPath`). To change them, edit `patient_portal/src` and rebuild.
- **`healthcare/public/dist/`, `dist/`, `node_modules/`, `__pycache__/`, `*.egg-info`, `healthcare/docs/current`:** gitignored build output. `healthcare/public/node_modules` is a gitignored symlink or install.
- **Translations:** `healthcare/locale/main.pot` is regenerated weekly by `generate-pot-file.yml` (`update_pot_file.sh`). `.po` files come from Crowdin (`crowdin.yml`).
- **Version string:** `healthcare/__init__.py` `__version__` is rewritten by semantic-release (`.releaserc`) on release branches.
- **Lockfiles:** `yarn.lock`. Update it with yarn, not by hand.
- **Frappe-managed JSON:** DocType `.json` schemas, workspaces, reports and print formats are normally changed through the Desk UI with developer mode and then exported. Keep edits structurally valid; upstream syncs merge `fields` / `field_order` as a union.
- **Type-annotation blocks** (`# begin: auto-generated types`) in DocType controllers are generated by Frappe from the JSON schema.
- **`.secrets.baseline`:** maintained by detect-secrets.
- **`.github/instructions/build-rules.instructions.md`** and the managed block in `AGENTS.md` are generated by Build from `.build/RULES.md`. Edit the source file instead.
