Do not edit these by hand:

- **`healthcare/public/frontend/`**: the committed Vite build of the patient portal (hashed `assets/patient_portal-*.js` / `.css` / `.map`, `index.html`, `manifest.json`). Regenerate it with `yarn build` from the `patient_portal/` sources and never edit the bundles directly. Pre-commit excludes `healthcare/public/frontend/assets/` and `healthcare/public/dist/`.
- **`healthcare/www/patient_portal.html`**: the frappe-ui Vite plugin writes this file (`indexHtmlPath`).
- **`patient_portal/auto-imports.d.ts`, `patient_portal/components.d.ts`**: type stubs generated by the frappe-ui and unplugin tooling.
- **`healthcare/locale/main.pot`**: regenerated by `.github/helper/update_pot_file.sh` and the weekly *Regenerate POT file* workflow. Crowdin PRs write the `.po` translations (`fix: %language% translations`).
- **`healthcare/__init__.py` version string**: semantic-release bumps it on release branches (`chore(release): Bumped to Version …`).
- **Lockfiles**: `yarn.lock`. Update it with yarn and never edit it by hand.
- **`.secrets.baseline`**: maintained by `detect-secrets`.
- **Ignored, never committed:** `dist/`, `node_modules/`, `__pycache__/`, `*.pyc`, `*.egg-info`, `healthcare/docs/current`, and the cloned `.frappe-semgrep-rules`.

DocType `.json` files are written by Frappe's DocType editor, but they are also edited in source. When resolving upstream conflicts, the ledger policy is a 3-way union of `fields` / `field_order`.
