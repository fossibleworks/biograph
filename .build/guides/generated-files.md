Never hand-edit these. Regenerate them with the owning tool.

- **Built portal assets:** `healthcare/public/frontend/assets/*` (hashed `patient_portal-<hash>.js/.css/.map`) and `healthcare/public/frontend/index.html` are committed Vite output. Pre-commit excludes `healthcare/public/frontend/assets/` and `healthcare/public/dist/`. Rebuild with `yarn build`. Note that `patient_portal/vite.config.js` sets `outDir` to `healthcare/public/patient_portal/assets` and the index HTML to `healthcare/www/patient_portal.html`. Check where output actually lands before committing a rebuild.
- **Auto-generated type declarations:** `patient_portal/auto-imports.d.ts` and `patient_portal/components.d.ts`, written by frappe-ui/unplugin.
- **Translation template:** `healthcare/locale/main.pot` is regenerated weekly by the `generate-pot-file.yml` workflow. `.po` files come from Crowdin (`crowdin.yml`).
- **Version string:** `healthcare/__init__.py` `__version__` is rewritten by semantic-release (`.releaserc` prepareCmd) and by `chore: bump version` commits.
- **Doctype JSON** (`doctype/*/*.json`, `workspace`, `report`, and so on) is normally written by Frappe's Desk UI in developer mode. Edit it carefully. Upstream sync merges it with a 3-way union of `fields`/`field_order`.
- **Lockfiles:** `yarn.lock`.
- **Ignored:** `*.pyc`, `__pycache__/`, `*.egg-info`, `dist/`, `node_modules/`, `healthcare/docs/current`, and `.ruff_cache`.
- `.secrets.baseline` is managed by detect-secrets.
- `.github/instructions/build-rules.instructions.md` and the guides block in `AGENTS.md` are generated by Build from `.build/RULES.md`. Edit the source instead.
